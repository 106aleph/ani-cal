# アニメ配信カレンダー

[しょぼいカレンダー](https://cal.syoboi.jp/) からアニメの配信予定を取得し、媒体を選んで登録 → カレンダーで確認 → 1話ごとに視聴記録できるセルフホストアプリです。

## 必要な環境

- Linux ホスト（動作確認: Debian 13）
- Git
- Docker と Docker Compose v2.24 以上
- Tailscale（tailnet で使う場合。管理画面で MagicDNS と HTTPS Certificates を有効化）
- `cal.syoboi.jp` と各社 Push サービスへの HTTPS 通信（外向き）

### 推奨スペック

- 2コア・2GB・空きディスク 5GB 以上

## セットアップ

```bash
git clone git@github.com:106aleph/ani-cal.git && cd ani-cal   # 非公開リポジトリ（SSH 鍵が必要）
cp .env.example .env              # SYOBOI_UA_URL を設定（下記）
docker compose up -d --build      # 初回取得は数分（docker compose logs -f で確認）
```

1. **管理者を登録**: ホスト上で `http://127.0.0.1:8000/` を開き、ユーザー名とパスワード（10文字以上）を決めて登録します（SSH なら `ssh -L 8000:127.0.0.1:8000 <ホスト>` で手元に転送）。最初のユーザーが管理者になり、以後この画面は使えません。以前のバージョンの登録作品・通知は、この管理者に引き継がれます。
2. **公開**: `sudo tailscale serve --bg 8000`（`APP_PORT` を変えた場合はその番号）。`https://<ホスト名>.<tailnet名>.ts.net/` を tailnet 内の端末で開きます。ブラウザからホーム画面やデスクトップにインストール（PWA）できます。

- `SYOBOI_UA_URL` には、連絡方法を載せた**誰でも見られる**ページのURL（非公開リポジトリのURLは不可）を設定します。しょぼいカレンダーへの User-Agent に入り、問題があれば運営から連絡できます。
- アプリのポートをインターネットへ直接公開しないでください。公開するときは「[公開するときのセキュリティ](#公開するときのセキュリティ)」に従います。
- サブパス公開（`--set-path`）は非対応です。他のサービスと併用するときは `--https=8443` など別ポートにしてください。

## 画面

| 画面 | できること |
|---|---|
| カレンダー | 月／週／リスト。視聴チェック、クリックで編集、深夜帯の「25:30」表記切替 |
| 作品一覧 | 媒体ごとの第1話日時つき一覧。媒体チップをクリックで登録。時期（クール）・媒体・配信系・未登録・タイトルで絞り込み |
| 登録作品 | 話数一覧、視聴チェック、話の追加・編集・削除、媒体の変更、タイトルの上書き、間隔指定での話の作成、一括視聴 |
| 視聴済み | 全話視聴した作品の置き場。「視聴済みに移す」で移動、「登録作品に戻す」で復帰。新しい話が追加されると自動で戻る |
| 視聴中断 | 途中で見るのをやめた作品の置き場。「視聴を中断」で移動、「登録作品に戻す」で復帰。自動では戻らない |
| 管理（管理者だけ） | しょぼいカレンダーの取得（今すぐ取得・期間指定・中断）、ユーザーと招待コードの管理、取得履歴 |

- 視聴済み・視聴中断の作品は、カレンダー・未視聴・通知・ICS に出ません。
- 編集した話は「修正済」になり、再取得で上書きされません（「取得値に戻す」可）。削除した話は「復元」できます。
- 取得データにない作品は「手動で作品を追加」、先の話数が未登録の作品は「間隔で話を作成」（予測。実データが入ると置き換わる）で扱えます。
- ICS 購読: アカウント →「カレンダー購読URL」に、自分専用のURL（`/calendar.ics?token=...`。`&unwatched_only=true` で未視聴のみ）が出ます。漏れたときは、同じ画面で作り直せます。

## ユーザーと権限

| | 管理者 | 一般 |
|---|---|---|
| 自分の登録作品・視聴記録・通知・購読URL | ○ | ○ |
| 「管理」タブ（取得操作・取得履歴・ユーザーと招待コードの管理） | ○ | ×（API も 403） |

- 登録作品・視聴記録・通知は**ユーザーごと**に別々です。しょぼいカレンダーから取得した作品は、全員で共有します。
- **新規登録には招待コードが必要です。** 管理者が「管理」タブで発行（1回限り・7日で失効）して本人に渡し、本人はログイン画面の「招待コードで新規登録」から登録します。
- **2段階認証**: アカウント →「2段階認証」で、Authy・Google Authenticator などに登録してオンにします（TOTP）。リカバリーコード（1回限り・8個）は、このとき**1度だけ**表示されるので保存してください。認証アプリを失くしたときは、リカバリーコードでログインするか、管理者が解除します。管理者は、既定で必須です（`REQUIRE_2FA`）。
- ユーザー名は半角英数字と `_ . -`（32文字以内）、パスワードは10文字以上です。最後の管理者の削除・降格はできません。ユーザーを削除すると、その人の登録作品と視聴記録も消えます。
- アカウント →「他の端末をすべてログアウト」で、この端末以外のログインを解除できます。
- 通知は、ログアウトするとその端末では止まります（ログインして「通知を有効にする」でやり直し）。

## 公開するときのセキュリティ

**手順**
1. HTTPS を終端するプロキシ（Tailscale Funnel、Caddy、Cloudflare Tunnel など）の後ろに置きます。アプリのポート（`127.0.0.1` のみ）を、直接公開しないでください。
2. 公開する前に、`http://127.0.0.1:8000/` で管理者を登録します。
3. `.env` を設定します。
   - `ALLOWED_HOSTS=cal.example.com` … 別のホスト名での要求を断ります（カンマ区切り）。
   - `REQUIRE_2FA=admin`（既定）/ `all` / `off` … 2段階認証を必須にする対象。公開するなら `all` を推奨します。
   - `COOKIE_SECURE=1` … プロキシが `X-Forwarded-Proto: https` を付けないときだけ必要です。
4. プロキシが `X-Forwarded-For` の**右端**に接続元を追記すること（一般的なプロキシは、そうなっています）。回数制限は、この値で数えます。

**入れている対策**
- **認証**: パスワードは Argon2id で保存し、10文字以上でユーザー名を含むものや定番のものは不可。ログインの失敗は、接続元＋ユーザー名で5回、ユーザー名で20回、接続元で30回に達すると、5分間止まります。2段階認証（TOTP）に対応し、管理者は既定で必須です。
- **セッション**: Cookie は HttpOnly・SameSite=Lax（https では Secure と `__Host-`）。DB には SHA-256 だけを保存し、作成から90日で必ず失効します。パスワード変更で、ほかの端末は解除されます。
- **登録**: 招待コード制です。最初のユーザーだけが管理者になります。
- **Web**: 状態を変える要求は、同一オリジンかつ JSON だけ受け付けます（CSRF 対策）。CSP・HSTS・`X-Frame-Options` などのヘッダを付け、本文は 256KB（認証まわりは 8KB）までです。
- **通知の送信先**: Google / Mozilla / Apple / Microsoft の Push サービスだけです。URL の細工は拒否し、リダイレクトも追いません。
- **データとコンテナ**: ユーザーごとにデータを分離しています。DB ファイルは所有者だけが読み書きできます（0600）。コンテナは非 root・読み取り専用で、不要な権限を削っています。
- **ログ**: ログインの成功・失敗や、権限・パスワードの変更を、接続元つきで記録します（`docker compose logs | grep auth`）。

**残るリスク**
- 購読 URL（`/calendar.ics?token=...`）のトークンは、プロキシのアクセスログに残る場合があります。漏れたら、アカウント画面から作り直してください。
- DB が盗まれると、2段階認証の秘密鍵が読めます。バックアップの保管に注意してください。
- OS・Docker・依存ライブラリは、定期的に更新してください（`docker compose build --pull`）。

## 通知

右上の「通知」→「通知を有効にする」で、登録作品の**未視聴の話**が開始の N 分前（既定10分、0〜1440）に、アプリを開いていなくても届きます。視聴済みに移した作品・非表示の話は対象外です。

- 分数は端末ごとの設定です。同じ画面から、テスト通知と停止もできます。
- HTTPS での接続が必要です。iPhone / iPad は、ホーム画面に追加したアプリ（iOS 16.4 以降）から有効にします。
- 送信先は Google / Mozilla / Apple / Microsoft の Push サービスに限定しています。
- 30秒おきに確認し、開始後3分までの話を送ります（それ以降は送りません）。
- VAPID 鍵は初回起動で生成して DB に保存します。連絡先は `PUSH_SUBJECT`（既定は `SYOBOI_UA_URL`）。

## 取得の仕組み

公式 API（`db.php`）を、[bot向けルール](https://docs.cal.syoboi.jp/rule/bot/)に沿って使います。

| 種類 | タイミング | 内容 |
|---|---|---|
| 初回 | DBが空のときの最初の1回 | 60日前〜120日先を2日ずつ（約90リクエスト、数分） |
| 定期・起動時・今すぐ | **6時間ごと**（10分おきに確認し、前回成功から6時間以上で実行） | 前回以降の更新分だけを**差分取得**（1回数リクエスト） |
| 期間指定 | 「管理」タブのボタン（片方の日付を選ぶともう片方が自動入力） | 指定した期間の予定を取得。**1回あたり最大90日、1日3回まで**（`RANGE_SYNC_DAILY_LIMIT`）。定期取得の「前回以降」の基準には影響しない |

- 間隔は `SYNC_INTERVAL_HOURS`（既定6、`0` で自動取得なし）。起動時も、前回成功から6時間以上のときだけ取得します。
- リクエストは直列・1.5秒間隔。`429`/`503` は `Retry-After` に従い、再試行は5回まで。待ちが5分を超えるときは待たず失敗として終え、ログに「制限されています」と残ります（`SYOBOI_MAX_WAIT_SEC`）。
- 自動取得が連続5回失敗すると停止します（画面に表示）。「今すぐ取得」の成功で再開します。
- 「中断」で取得を止められます。取得済みの分は保存され、失敗には数えません。
- 登録作品への反映は取得成功時の最後に行います（「定期取得で自動更新」がオンの作品のみ）。
- 放送開始が古い作品や取りこぼしは「期間指定」で取り直します。広い範囲は90日ずつ分け、429 を受けたら30分〜1時間空けます。
- **作品一覧**: 取得済みのアニメ（放送中・終了のカテゴリ。`NEW_CATS`）を、放送開始のクールごとに出します。古い作品は「期間指定」で取得すると、「時期」から選べます。**配信系**: チャンネルグループ名に「ネット/インターネット/配信/web」を含む媒体（`NET_GROUP_IDS` で指定も可）。
- 設定項目は `.env.example` にあります。

## 運用

```bash
docker compose ps                                        # healthy ならOK
docker compose logs --tail 20
curl -s http://127.0.0.1:8000/api/health; echo           # 稼働確認（/api/status などは、ログインが必要）
git pull && docker compose up -d --build                 # 更新（ソースだけの再ビルドは約1分）
sudo sqlite3 data/anime.db ".backup $HOME/backup-$(date +%F).db"   # バックアップ（要 sqlite3。DB はコンテナ用ユーザーの所有なので sudo）
docker compose down                                      # 停止
sudo tailscale serve --https=443 off                     # serve の設定を外す
```

**ログインできなくなったとき（管理者のパスワードや認証アプリを失くした場合など）**は、ホストで次を実行します。`-u app` は必須です（root で実行すると DB の関連ファイルが root の所有になり、アプリが起動できなくなるため、root では実行を断ります）。

```bash
docker compose exec -u app app ani-cal user list                       # ユーザー一覧
docker compose exec -u app app ani-cal user reset-password <ユーザー名>  # 仮パスワードを表示（ログインはすべて解除）
docker compose exec -u app app ani-cal user reset-2fa <ユーザー名>       # 2段階認証を解除（ログインはすべて解除）
```

仮パスワードは、その場で1回だけ表示されます。ログイン後、すぐにアカウント画面から変更してください。サーバーのシェルに入れる人だけが使えるコマンドです。

データは `./data/anime.db` にあります。取得中に停止すると、ログに「中断されました」と残り、次回の取得でやり直します。

## 開発

```bash
cd app
DB_PATH=./dev.db BIND=127.0.0.1:8000 cargo run   # http://127.0.0.1:8000/
```

Rust 1.85 以上。画面（`app/static/`）はビルド時にバイナリへ埋め込むので、変更したら再ビルドします。

## API（参考）

| メソッド | パス | 内容 |
|---|---|---|
| GET/POST | `/api/auth/setup` | 最初の管理者の登録待ちか（`{needed}`）／登録（ユーザーがいない間だけ。`{username, password}`） |
| POST | `/api/auth/login` / `register` / `logout` / `logout_others` | ログイン／招待コードでの新規登録（`{code, username, password}`）／ログアウト（Cookie）／ほかの端末をログアウト |
| POST | `/api/auth/totp/setup` / `enable` / `disable` | 2段階認証の設定開始（鍵とQR）／有効化（`{code}`、リカバリーコードを返す）／無効化（`{password, code}`）。ログインは `{username, password, otp}`、`otp` なしだと `{totp_required:true}` |
| GET/POST/DELETE | `/api/invites` / `/api/invites/{id}` | 招待コードの一覧・発行・取り消し（admin） |
| GET/POST | `/api/auth/me` / `password` / `ics_token` | 自分の情報／パスワード変更／購読URLの作り直し |
| GET/PATCH/DELETE | `/api/users` / `/api/users/{id}` | ユーザー管理（admin） |
| GET | `/api/health` / `/api/status` | 稼働確認／取得状況 |
| POST | `/api/sync` | 取得開始（本文 `{start, end}` で期間指定）（admin） |
| POST | `/api/sync/cancel` | 取得の中断（admin） |
| GET | `/api/logs` | 取得履歴（admin） |
| GET | `/api/coverage` | 取得済みの日付範囲（admin） |
| GET | `/api/catalog` / `/api/titles/{tid}/channels` | 作品一覧／作品の媒体別の放送 |
| GET/POST | `/api/tracks` | 登録作品の一覧（`?archived=true` で視聴済み、`?dropped=true` で視聴中断）／登録 |
| PATCH/DELETE | `/api/tracks/{id}` | 作品の編集／解除 |
| POST | `/api/tracks/{id}/generate` / `watch_all` | 予測話の作成／一括視聴 |
| POST | `/api/tracks/{id}/resync` | 取得データの再反映 |
| POST | `/api/tracks/{id}/archive` / `drop` / `unarchive` | 視聴済みへ移す／視聴中断へ移す／登録作品へ戻す |
| GET/POST | `/api/tracks/{id}/episodes` | 話の一覧／追加 |
| PATCH/DELETE | `/api/episodes/{id}` | 話の編集／削除 |
| POST | `/api/episodes/{id}/revert` | 取得値に戻す |
| GET/POST | `/api/push/{key,settings,subscribe,unsubscribe,test}` | 通知の購読と設定 |
| GET | `/api/calendar?start=&end=` / `/api/backlog` | 期間内の話／配信済みで未視聴の話 |
| GET | `/calendar.ics?token=` | iCalendar（ユーザーごと） |
