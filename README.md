# アニメ配信カレンダー

[しょぼいカレンダー](https://cal.syoboi.jp/) からアニメの配信予定を取得し、媒体を選んで登録 → カレンダーで確認 → 1話ごとに視聴記録できるセルフホストアプリです。

## 必要な環境

- Linux ホスト（動作確認: Debian 13）
- Docker と Docker Compose
- Tailscale（管理画面で MagicDNS と HTTPS Certificates を有効化）
- `cal.syoboi.jp` と各社 Push サービスへの HTTPS 通信（外向き）

### 推奨スペック

- 2コア・2GB・空きディスク 5GB 以上
- 動かすだけなら非常に軽い（メモリ約 10〜15MB）。必要なのは**ビルドのときだけ**（初回は約5分）
- メモリが 1GB 以下だとビルドが `Killed` になることがある。スワップを足すか、別のマシンでビルドする

## セットアップ

```bash
git clone git@github.com:106aleph/ani-cal.git && cd ani-cal   # 非公開リポジトリ（SSH 鍵が必要）
cp .env.example .env              # SYOBOI_UA_URL を設定（下記）
docker compose up -d --build
docker compose logs -f            # 初回取得は数分
# ↓ の前に、ホスト上で http://127.0.0.1:8000/ を開いて、管理者を登録する（下記）
sudo tailscale serve --bg 8000    # APP_PORT を変えた場合はその番号
```

`https://<ホスト名>.<tailnet名>.ts.net/` を tailnet 内の端末で開きます。ブラウザからホーム画面やデスクトップにインストール（PWA）できます。

- `.env` の `SYOBOI_UA_URL` に、連絡方法を載せた**誰でも見られる**ページのURL（非公開リポジトリのURLは不可）を設定します。しょぼいカレンダーへの User-Agent（`AnimeCalendar/1.0 (+URL)`）に入り、問題があれば運営から連絡できます。変更後は `docker compose up -d`。
- コンテナは `127.0.0.1` にしか公開せず、アクセスは `tailscale serve` 経由のみです。**アプリのポートをインターネットへ直接公開しないでください**（HTTPS の終端と、遅い接続による攻撃への備えは、手前のプロキシに任せる設計です）。インターネットに公開するときは、下の「[公開するときのセキュリティ](#公開するときのセキュリティ)」に従ってください。
- **最初にアクセスした人が管理者になります。** ユーザーが1人もいない間は、ログイン画面の代わりに「管理者の登録」画面が出るので、ユーザー名とパスワード（10文字以上）を決めて登録します（招待コードは不要）。パスワードを設定ファイルに書く必要はなく、ユーザー名も自分で決められます。登録が済むと、この画面は二度と使えません。**`tailscale serve` で公開する前に**、ホスト上の `http://127.0.0.1:8000/`（SSH なら `ssh -L 8000:127.0.0.1:8000 <ホスト>` で手元に転送）を開いて登録してください。コンテナは `127.0.0.1` にしか公開していないので、公開前は自分しか開けません。以前のバージョンで登録した作品・通知は、この管理者に引き継がれます。
- サブパス公開（`--set-path`）は非対応です。他のサービスと併用するときは `--https=8443` など別ポートにしてください。

## 画面

| 画面 | できること |
|---|---|
| カレンダー | 月／週（時間軸・現在時刻の線つき）／リスト（月ごと）。視聴チェック、クリックで編集、深夜帯の「25:30」表記切替 |
| 作品一覧 | 媒体ごとの第1話日時つき一覧。媒体チップをクリックで登録。時期（クール）・媒体・配信系・未登録・タイトルで絞り込み。取得済みの過去のクールも「時期」で選べる |
| 登録作品 | 話数一覧、視聴チェック、話の追加・編集・削除、媒体の変更、タイトル／媒体名の上書き、間隔指定での話の作成、一括視聴、ICS 出力 |
| 視聴済み | 全話視聴した作品の置き場（放送クールの新しい順、クール内は名前順で、境目にクールを表示）。「登録作品」の「視聴済みに移す」（全話視聴済みのときだけ押せる）で移動、「登録作品に戻す」で復帰。カレンダー・未視聴・ICS には出ない。新しい話が追加されると自動で戻る |
| 視聴中断 | 途中で見るのをやめた作品の置き場（並びは視聴済みと同じ）。「登録作品」の「視聴を中断」でいつでも移動、「登録作品に戻す」で復帰。カレンダー・未視聴・通知・ICS には出ない。新しい話が追加されても自動では戻らない |
| 管理（管理者だけ） | 管理者向けの操作を1か所にまとめたタブです。①**しょぼいカレンダーの取得**（今すぐ取得・期間指定・中断と、取得の状況）、②**ユーザーと招待**（招待コードの発行・取り消し、権限の変更、パスワード再設定、2段階認証の解除、削除。各ユーザーの登録日と最終ログインも表示）、③**取得履歴**（取得済みの日付範囲（初回・期間指定の合計）と、日時・種別・範囲・結果・所要時間・件数。画面は最新200件、保存は500件まで）。一般ユーザーには、タブも API も出ません |

- 編集した話は「修正済」になり、再取得で上書きされません（「取得値に戻す」可）。削除した話は復活しません（「復元」可）。
- 取得データにない作品は「手動で作品を追加」、先の話数が未登録の作品は「間隔で話を作成」（予測。実データが入ると置き換わり、視聴記録は保持）で扱えます。
- ICS 購読: 右上のアカウント →「カレンダー購読URL」に、自分専用のURL（`/calendar.ics?token=...`。`&unwatched_only=true` で未視聴のみ）が出ます。購読ソフトはログインできないので、URLのトークンで認証します。漏れたときは、同じ画面で作り直せます。tailnet 外のサービスからは取得できません。

## ユーザーと権限

右上のアカウントから、ログアウト・パスワード変更・購読URLの確認ができます。

| | 管理者（admin） | 一般（user） |
|---|---|---|
| 自分の登録作品・視聴記録・通知・購読URL | ○ | ○ |
| しょぼいカレンダーから取得した作品の閲覧 | ○ | ○ |
| 今すぐ取得・期間指定・中断（「管理」タブ） | ○ | ×（タブもボタンも出ない。API も 403） |
| 取得履歴・取得済みの期間の閲覧（「管理」タブ） | ○ | ×（API も 403） |
| 招待コードの発行・権限変更・パスワード再設定・2段階認証の解除・削除（「管理」タブ） | ○ | × |

- 登録作品・視聴記録・通知の設定は、**ユーザーごと**に別々です。しょぼいカレンダーから取得した作品（作品一覧のもとになるデータ）は、全員で共有します。
- **新規登録には、管理者が発行した招待コードが必要です。** 管理者が「管理」タブの「招待コードを発行」でコード（1回だけ使え、7日で期限切れ。権限を選べる）を作って本人に渡し、本人はログイン画面の「招待コードで新規登録」から、ユーザー名とパスワードを決めて登録します。ログインは、これまで通りユーザー名とパスワードです。コードの入力に、同じ接続元から5回（全体で20回）失敗すると、5分間止まります。
- **2段階認証（任意・ユーザーごと）**: アカウント →「2段階認証」で、QRコード（またはキーの手入力）を Authy・Google Authenticator・1Password などの認証アプリに登録し、6桁のコードを入力してオンにします（標準の TOTP：SHA-1・6桁・30秒）。オンにすると、ログインのたびにユーザー名・パスワードに加えて6桁のコードが必要です。このとき**リカバリーコード（1回限り・8個）が1度だけ表示される**ので保存してください。認証アプリを失くしたときは、リカバリーコードでログインするか、管理者が「管理」タブから解除します。オフにするには、パスワードと認証コードが必要です。同じコードの使い回しはできません。
- ユーザー名は半角英数字と `_ . -`（32文字以内）、パスワードは10文字以上（ユーザー名を含むものや、よくあるパスワードは不可）です。最後の管理者の削除・降格はできません。ユーザーを削除すると、その人の登録作品と視聴記録も消えます。
- パスワードは Argon2id で保存します。ログインは Cookie（30日、使うと延長。作ってから90日で必ず切れる）です。ログインの失敗は、同じ接続元から同じユーザー名で5回続けると、その接続元が5分間ロックされます（他の端末の人は影響を受けません）。接続元を変えながらの試行には、ユーザー名ごとに20回、ユーザー名を変えながらの試行（パスワードスプレー）には、接続元ごとに30回の上限があります。
- 右上のアカウント →「他の端末をすべてログアウト」で、この端末以外のログインを解除できます。
- 管理者は、既定で**2段階認証が必須**です（`REQUIRE_2FA`）。管理者を登録した直後に、設定を求められます。
- 通知は、ログアウトするとその端末では止まります（ログインして「通知を有効にする」でやり直し）。

## 公開するときのセキュリティ

インターネットに公開する可能性があるので、次の対策を入れています。公開するときは、手順も守ってください。

**手順**
1. **構成**: アプリ本体は `127.0.0.1` だけで待ち受けます。公開は、HTTPS を終端するプロキシ（Tailscale Funnel、Caddy、Cloudflare Tunnel など）の後ろに置いてください。アプリのポートを直接公開するのは非推奨です（Rust の小さな HTTP サーバーなので、遅い接続を延々と続ける攻撃などへの備えは、プロキシ側に任せます）。
2. **先に管理者を登録**: 公開する前に、`http://127.0.0.1:8000/` で管理者を登録します（上のセットアップ参照）。
3. **`.env` の設定**:
   - `ALLOWED_HOSTS=cal.example.com`（公開するホスト名。カンマ区切り）… 別のホスト名での要求を断ります。
   - `COOKIE_SECURE=1` … プロキシが `X-Forwarded-Proto: https` を付けない構成のときだけ必要です（付く構成では、自動で Secure になります）。
   - `REQUIRE_2FA=admin`（既定）/ `all` / `off` … 2段階認証を必須にする対象。公開するなら `all` を推奨します。
4. **プロキシの条件**: `X-Forwarded-For` に、**接続元をいちばん右へ追記**してくれること（一般的なプロキシは、そうなっています）。回数制限は、この値の右端を接続元として数えます。

**入れている対策**

| 項目 | 内容 |
|---|---|
| パスワード | Argon2id。10文字以上、ユーザー名を含むもの・よくあるもの・同じ文字の繰り返しは不可。同時に走らせるハッシュ計算に上限 |
| ログイン | 失敗の回数制限（接続元＋ユーザー名 5 回／ユーザー名 20 回／接続元 30 回、5分）。ログイン・登録は接続元ごとに 1 分 20 回まで。存在しないユーザー名でも処理時間が変わらない |
| 2段階認証 | TOTP（Authy など）。リカバリーコードは1回限り。使った認証コードは再利用不可。管理者は既定で必須 |
| セッション | Cookie は HttpOnly・SameSite=Lax・https では Secure と `__Host-` 付き。DB には SHA-256 だけを保存。作成から90日で必ず失効。パスワード変更・再設定でほかの端末は解除 |
| 登録 | 招待コード制（1回限り・7日で失効）。最初のユーザーだけが管理者になり、以後は閉じる |
| CSRF | 状態を変える要求は、同一オリジン（`Sec-Fetch-Site` / `Origin`）かつ `application/json` のときだけ受け付ける |
| ヘッダ | CSP（自分のオリジン以外のスクリプト・接続を禁止）、HSTS、`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy: no-referrer`、COOP / CORP、`Permissions-Policy` |
| 入力 | 本文は 256KB（認証まわりは 8KB）まで。SQL は常にバインド。画面側は出力をエスケープ |
| 通知の送信先 | Google / Mozilla / Apple / Microsoft の Push サービスだけ。URL の解釈の違いを突く書き方（`\` `@` `#` など）は拒否し、リダイレクトも追わない |
| データ | ユーザーごとに登録データを分離。DB ファイルは所有者だけが読み書き（0600） |
| コンテナ | 非 root、読み取り専用のファイルシステム、不要な権限（capabilities）を削除、`no-new-privileges`、メモリ・プロセス数の上限 |
| ログ | ログインの成功・失敗、ロック、2段階認証の失敗、権限・パスワードの変更を、接続元つきで記録（`docker compose logs \| grep auth`）。ユーザー名などは、改行を除いて記録 |

**残るリスクと運用**
- 購読 URL（`/calendar.ics?token=...`）のトークンは URL に入るため、プロキシのアクセスログに残る場合があります。漏れたら、アカウント画面から作り直してください。
- DB が盗まれると、2段階認証の秘密鍵が読めます（パスワードは Argon2id のハッシュです）。バックアップの保管に注意してください。
- OS・Docker・依存ライブラリは、定期的に更新してください（`git pull && docker compose up -d --build` でベースイメージも取り直す）。ログに `login failed` が大量に出たときは、プロキシ側で接続元を制限してください。

## 通知

右上の「通知」→「通知を有効にする」で、登録作品の**未視聴の話**が開始の N 分前（既定10分、0〜1440）に、アプリを開いていなくても届きます。視聴済みに移した作品・非表示の話は対象外です。

- 分数は端末ごとの設定です。同じ画面から、テスト通知と停止もできます。
- HTTPS での接続が必要です。iPhone / iPad は、ホーム画面に追加したアプリ（iOS 16.4 以降）から有効にします。
- 送信先は Google / Mozilla / Apple / Microsoft の Push サービスに限定しています。
- 30秒おきに確認し、開始後3分までの話を送ります（それ以降は送りません）。
- VAPID 鍵は初回起動で生成して DB に保存します。連絡先は `PUSH_SUBJECT`（既定は `SYOBOI_UA_URL`）。

## 取得の仕組み

公式 API（`db.php`）を、[bot向けルール](https://docs.cal.syoboi.jp/rule/bot/)に沿って使います。

| 種類 | タイミング | 内容 |
|---|---|---|
| 初回 | DBが空のときの最初の1回 | 60日前〜120日先を2日ずつ（約90リクエスト、数分） |
| 定期・起動時・今すぐ | **6時間ごと**（10分おきに確認し、前回成功から6時間以上で実行） | 前回以降の更新分だけを**差分取得**（1回数リクエスト） |
| 期間指定 | 「管理」タブのボタン（片方の日付を選ぶともう片方が自動入力） | 指定した期間の予定を取得。**1回あたり最大90日、1日3回まで**（`RANGE_SYNC_DAILY_LIMIT`）。定期取得の「前回以降」の基準には影響しない |

- 間隔は `SYNC_INTERVAL_HOURS`（既定6、`0` で自動取得なし）。起動時も、前回成功から6時間以上のときだけ取得します。
- リクエストは直列・1.5秒間隔。`429`/`503` は `Retry-After` に従い、再試行は5回まで。待ちが5分を超えるときは待たず失敗として終え、ログに「制限されています」と残ります（`SYOBOI_MAX_WAIT_SEC`）。
- 自動取得が連続5回失敗すると停止します（画面に表示）。「今すぐ取得」の成功で再開します。
- 「中断」で取得を止められます。取得済みの分は保存され、失敗には数えません。
- 登録作品への反映は取得成功時の最後に行います（「定期取得で自動更新」がオンの作品のみ）。
- 放送開始が古い作品や取りこぼしは「期間指定」で取り直します。広い範囲は90日ずつ分け、429 を受けたら30分〜1時間空けます。
- **作品一覧**: 取得済みのアニメ（放送中・終了のカテゴリ。`NEW_CATS`）を、放送開始のクールごとに出します。古い作品は「期間指定」で取得すると、「時期」から選べます。**配信系**: チャンネルグループ名に「ネット/インターネット/配信/web」を含む媒体（`NET_GROUP_IDS` で指定も可）。
- 設定項目は `.env.example` にあります。

## 運用

```bash
docker compose ps                                        # healthy ならOK
docker compose logs --tail 20
curl -s http://127.0.0.1:8000/api/health; echo           # 稼働確認（/api/status などは、ログインが必要）
git pull && docker compose up -d --build                 # 更新（ソースだけの再ビルドは約1分）
sudo sqlite3 data/anime.db ".backup $HOME/backup-$(date +%F).db"   # バックアップ（要 sqlite3。DB はコンテナ用ユーザーの所有なので sudo）
docker compose down                                      # 停止
sudo tailscale serve --https=443 off                     # serve の設定を外す
```

**ログインできなくなったとき（管理者のパスワードや認証アプリを失くした場合など）**は、ホストで次を実行します。`-u app` は必須です（root で実行すると DB の関連ファイルが root の所有になり、アプリが起動できなくなるため、root では実行を断ります）。

```bash
docker compose exec -u app app ani-cal user list                       # ユーザー一覧
docker compose exec -u app app ani-cal user reset-password <ユーザー名>  # 仮パスワードを表示（ログインはすべて解除）
docker compose exec -u app app ani-cal user reset-2fa <ユーザー名>       # 2段階認証を解除（ログインはすべて解除）
```

仮パスワードは、その場で1回だけ表示されます。ログイン後、すぐにアカウント画面から変更してください。サーバーのシェルに入れる人だけが使えるコマンドです。

データは `./data/anime.db` にあります。取得中に停止すると、ログに「中断されました」と残り、次回の取得でやり直します。

## 開発

```bash
cd app
DB_PATH=./dev.db BIND=127.0.0.1:8000 cargo run   # http://127.0.0.1:8000/
```

Rust 1.85 以上。画面（`app/static/`）はビルド時にバイナリへ埋め込むので、変更したら再ビルドします。

## API（参考）

| GET | `/api/health` / `/api/status` | 稼働確認／取得状況 |
| POST | `/api/sync` | 取得開始（本文 `{start, end}` で期間指定）（admin） |
| POST | `/api/sync/cancel` | 取得の中断（admin） |
| GET | `/api/logs` | 取得履歴（admin） |
