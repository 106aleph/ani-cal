# アニメ配信カレンダー

[しょぼいカレンダー](https://cal.syoboi.jp/) からアニメの配信予定を取得し、見たい作品を配信媒体ごとに登録できます。カレンダーで予定を確認しながら、1話ずつ視聴記録をつけられます。セルフホスト型で、仲間内の数人で使うことを想定しています。

## 必要な環境

- Linux ホスト (動作確認: Debian 13)
- 2コア・2GB・空きディスク 5GB 以上 (ビルド時。起動後は約 10〜15MB で動作)
- Docker と Docker Compose v2.24 以上 (Rust のツールチェーンはホストに不要)
- Git
- Tailscale (tailnet で使う場合。MagicDNS と HTTPS Certificates を有効化)
- 外向きの HTTPS 通信
  - 実行時: `cal.syoboi.jp` と各社 Push サービス (Turnstile を使う場合は `challenges.cloudflare.com` も)
  - ビルド時: Docker Hub・crates.io・Alpine のパッケージサーバー
- sqlite3 (バックアップを取る場合のみ)

アプリは1つのコンテナで動き、ビルドはコンテナの中で行われます。

## セットアップ

```bash
git clone https://github.com/106aleph/ani-cal.git && cd ani-cal
cp .env.example .env              # SYOBOI_UA_URL を設定 (下記)
docker compose up -d --build      # 初回取得は数分 (docker compose logs -f で確認)
```

1. **管理者を登録**: ホスト上で `http://127.0.0.1:8000/` を開き、ユーザー名とパスワード (10文字以上)を決めて登録します。最初のユーザーが管理者になり、以後この画面は使えません。SSH で入っている場合は、`ssh -L 8000:127.0.0.1:8000 <ホスト>` で手元に転送すると開けます。以前のバージョンの登録作品・通知は、この管理者に引き継がれます。
2. **公開**: `sudo tailscale serve --bg 8000` を実行します (`APP_PORT` を変えた場合はその番号)。tailnet 内の端末から `https://<ホスト名>.<tailnet名>.ts.net/` を開いて使います。ブラウザからホーム画面やデスクトップにインストール (PWA) もできます。

- `SYOBOI_UA_URL` には、**自分への**連絡方法を載せた、誰でも見られるページの URL を設定します。この URL がしょぼいカレンダーへの User-Agent に入り、問題があれば運営から連絡できます。このリポジトリの連絡先は作者のものなので、自分で運用するときは使わないでください。
- アプリのポートをインターネットへ直接公開しないでください。公開するときは「[公開するときのセキュリティ](#公開するときのセキュリティ)」に従ってください。
- サブパス公開 (`--set-path`) は非対応です。他のサービスと併用するときは、`--https=8443` など別ポートにしてください。

## 画面

| 画面 | できること |
|---|---|
| 作品一覧 | 媒体ごとの第1話日時つき一覧。媒体チップをクリックで登録。時期 (クール)・媒体・配信系・未登録・配信中・タイトルで絞り込み |
| カレンダー | 月／週／リスト。視聴チェック、クリックで編集、深夜帯の「25:30」表記切替 |
| 登録作品 | 話数一覧、視聴チェック、話の追加・編集・削除、媒体の変更、タイトルの上書き、間隔指定での話の作成、一括視聴。次の配信が近い順に並び、作品名の横に放送時期を表示 |
| 視聴済み | 全話視聴した作品の置き場。「視聴済みに移す」で移動、「登録作品に戻す」で復帰。新しい話が追加されると自動で戻る |
| 視聴中断 | 途中で見るのをやめた作品の置き場。「視聴中断」で移動、「登録作品に戻す」で復帰。自動では戻らない |
| 管理 (管理者だけ) | しょぼいカレンダーの取得 (今すぐ取得・期間指定・中断。期間指定は今日の回数と残りを表示)、ユーザーと招待コードの管理、Botプロテクション (Turnstile) の設定、取得履歴 |

- 画面上部の「最終取得」の横に、取得済みの期間を表示します。
- 視聴済み・視聴中断の作品は、カレンダー・未視聴・通知に出ません。
- 作品一覧の媒体チップは、視聴済みが緑、視聴中断が黄色のラベルで区別します。
- 「配信中のみ」は、第1話の配信が始まっていて、最後の話がまだ先の媒体だけを出します。
- 作品一覧の放送時期は、作品の初回放送の時期です。長寿番組は古い時期になります。
- 編集した話は「修正済」になり、再取得で上書きされません。「取得値に戻す」で戻せます。削除した話は「復元」できます。
- 取得データにない作品は、「手動で作品を追加」で登録します。先の話数が未登録の作品は、「間隔で話を作成」で話を作ります。作成した話は予測で、実データが入ると置き換わります。

## ユーザーと権限

| | 管理者 | 一般 |
|---|---|---|
| 自分の登録作品・視聴記録・通知 | ○ | ○ |
| 「管理」タブ (取得操作・取得履歴・ユーザーと招待コードの管理) | ○ | × (API も 403) |

- **データ**: 登録作品・視聴記録・通知はユーザーごとに別々です。しょぼいカレンダーから取得した作品は、全員で共有します。
- **登録**: 新規登録には招待コードが必要です。管理者が「管理」タブで発行して、本人に渡します。コードは1回限りで、7日で失効します。本人は、ログイン画面の「招待コードで新規登録」から登録します。
- **2段階認証**: アカウント →「2段階認証」で、Authy や Google Authenticator などに登録してオンにします (TOTP)。このとき、リカバリーコード (1回限り・8個) が**1度だけ**表示されるので、保存してください。認証アプリを失くしたときは、リカバリーコードでログインするか、管理者に解除してもらいます。オン・オフを切り替えると、ほかの端末のログインは解除されます。管理者は、既定で必須です (`REQUIRE_2FA`)。
- **ユーザー一覧**: 「管理」タブで、登録日・最終ログイン・最終利用を確認できます。最終利用は、ログイン中の端末の最後の利用で、ログアウトすると残りません。
- **ユーザー名とパスワード**: ユーザー名は半角英数字と `_ . -` (32文字以内)、パスワードは10文字以上です。最初の管理者 (いちばん早く作られた管理者) は、削除も降格もできません。ユーザーを削除すると、その人の登録作品と視聴記録も消えます。
- **ログイン**: アカウント →「ログイン中の端末」で、ログインしている端末 (ブラウザの種類・接続元・最終利用) の一覧を確認できます。心当たりのない端末は、1つずつ、またはまとめてログアウトさせられます。
- **通知**: ログアウトすると、その端末では止まります。ログインして「通知を有効にする」からやり直してください。

## 公開するときのセキュリティ

**手順**
1. HTTPS を終端するプロキシ (Tailscale Funnel、Caddy、Cloudflare Tunnel など) の後ろに置きます。アプリのポート (`127.0.0.1` のみ) を、直接公開しないでください。
2. 公開する前に、`http://127.0.0.1:8000/` で管理者を登録します。
3. `.env` を設定します。
   - `ALLOWED_HOSTS=cal.example.com`: 別のホスト名での要求を断ります (カンマ区切り)。
   - `REQUIRE_2FA=admin` (既定) / `all` / `off`: 2段階認証を必須にする対象です。公開するなら `all` を推奨します。
   - `COOKIE_SECURE=1`: プロキシが `X-Forwarded-Proto: https` を付けないときだけ必要です。
4. 必要なら、「管理」タブの「Botプロテクション」で Cloudflare Turnstile を設定します。Cloudflare のダッシュボードでウィジェットを作り、サイトキーとシークレットキーを入力します。保存すると、ログインと新規登録にBotプロテクションが付きます。tailnet だけで使うなら不要です。
5. 回数制限は、`X-Forwarded-For` の**右端**を接続元として数えます。プロキシがこの値に接続元を追記することを確認してください (一般的なプロキシは追記します)。この値は、信頼するプロキシ (既定は、同じ機械と Docker・家庭内などの私的なアドレス) から来た要求のものだけ使い、それ以外は直接の接続元で数えます。プロキシが別のホストにあるときは、`TRUSTED_PROXIES` にそのアドレスを入れます。

**Cloudflare Tunnel で公開する場合**
1. `ALLOWED_HOSTS` には、公開するホスト名に加えて、tailnet のホスト名も入れます。入れないと、tailnet からのアクセスが断られます。
2. Cloudflare Access を使うなら、Tunnel の経路より**先に**アプリケーションを作ります。Access のない経路は、だれでも届くためです。
3. Zero Trust の「Networking → Tunnels」でトンネルを作り、表示されるコマンドをサーバーで実行します。経路 (Published application) の Service URL は、`http://localhost:8000` にします。
4. Turnstile のウィジェットは、許可ホスト名を公開するドメインだけにします。キーは、公開の URL でログインして、「管理」タブで入力します。
5. Turnstile は、tailnet のホスト名でのログインにも効きます。許可ホスト名に入れられず、確認が通らない場合は、新しいログインを公開の URL で行うか、一時的に無効にします。
6. 公開したら、ログインの記録 (`docker compose logs | grep auth`) の `ip=` が、本物の接続元であることを確認します。
7. 緊急時は、`sudo systemctl stop cloudflared` で公開を止めます。Turnstile で入れなくなったときは、「運用」の `turnstile off` を使います。

**入れている対策**
- **認証**: パスワードは Argon2id で保存します。10文字以上で、ユーザー名を含むものや定番のものは使えません。ログインに失敗すると、次の上限で5分間止まります (接続元とユーザー名の組で5回、ユーザー名で20回、接続元で30回)。2段階認証 (TOTP) の認証コードの確認も、同じ上限で止まります。2段階認証に対応し、管理者は既定で必須です。Turnstile を設定すると、Botプロテクションを通らない要求は、パスワードの照合や失敗の回数に入る前に断ります。シークレットキーは DB に保存し、画面には表示しません。設定と無効化には、パスワードの確認が要ります。
- **セッション**: Cookie は HttpOnly・SameSite=Lax です (https では Secure と `__Host-` も付きます)。DB には SHA-256 だけを保存します。セッションは、作成から90日で必ず失効します。パスワードの変更や、2段階認証のオン・オフを切り替えたときは、ほかの端末のログインを解除します。
- **登録**: 最初のユーザーが管理者になり、以後は招待コード制です。権限は、招待コードの発行時に選びます。
- **Web**: 状態を変える要求は、同一オリジンかつ JSON のものだけ受け付けます (CSRF 対策)。CSP・HSTS・`X-Frame-Options` などのヘッダも付けます。本文の上限は 256KB (認証まわりは 8KB) です。ヘッダや本文を15秒以上止めて送る接続と、15秒以上何も流れない接続は、切ります。Turnstile を使うときだけ、CSP で `challenges.cloudflare.com` の script と枠を許可します。
- **通知の送信先**: Google / Mozilla / Apple / Microsoft の Push サービスだけです。URL の細工は拒否し、リダイレクトも追いません。
- **データとコンテナ**: ユーザーごとにデータを分離しています。DB ファイルは所有者だけが読み書きできます (0600)。コンテナは非 root・読み取り専用で、不要な権限を削っています。ベースイメージは digest で固定し、GitHub Actions (Trivy) で既知の脆弱性を毎週調べます。
- **ログ**: ログインの成功・失敗を、接続元つきで記録します。権限とパスワードの変更も記録します。`docker compose logs | grep auth` で確認できます。

## 通知

右上の「通知」→「通知を有効にする」で、通知がオンになります。登録作品の未視聴の話が、開始の N 分前 (既定10分、0〜1440) に届きます。アプリを開いていなくても届きます。

- 分数は端末ごとの設定です。テスト通知と停止も、同じ画面でできます。
- HTTPS での接続が必要です。iPhone / iPad は、ホーム画面に追加したアプリ (iOS 16.4 以降) から有効にします。
- 30秒おきに確認し、開始後3分までの話を送ります。
- VAPID 鍵は初回起動で生成して DB に保存します。連絡先は `PUSH_SUBJECT` です (既定は `SYOBOI_UA_URL`)。

## 取得の仕組み

公式 API (`db.php`) を、[bot 向けルール](https://docs.cal.syoboi.jp/rule/bot/)に沿って使います。

| 種類 | タイミング | 内容 |
|---|---|---|
| 初回 | DB が空のときの最初の1回 | 60日前〜120日先を2日ずつ (数分) |
| 定期・起動時・今すぐ | 6時間ごと (`SYNC_INTERVAL_HOURS`。`0` で自動取得なし) | 前回以降の更新分だけを差分取得 |
| 期間指定 | 「管理」タブ | 指定した期間を取得。1回最大90日、1日3回まで (`RANGE_SYNC_DAILY_LIMIT`) |

- リクエストは直列で、1.5秒間隔です。`429` / `503` は `Retry-After` に従います。待ちが5分を超えるときは、失敗として終えます (`SYOBOI_MAX_WAIT_SEC`)。
- 429 を受けると、自動取得は3時間止まります。連続5回失敗しても停止します (画面に表示)。「今すぐ取得」が成功すると再開します。「中断」しても、取得済みの分は保存されます。
- 取得したデータは、取得の成功時に、登録作品へ反映します。対象は、「定期取得で自動更新」がオンの作品だけです。
- 古い作品や取りこぼしは、「期間指定」で取り直します。広い範囲は90日ずつ分け、429 を受けたら30分〜1時間空けてください。
- **作品一覧**: 取得済みのアニメ (`NEW_CATS`) を、放送開始のクールごとに出します。
- **配信系**: チャンネルグループ名に「ネット/インターネット/配信/web」を含む媒体です。`NET_GROUP_IDS` で、ID を指定することもできます。
- 設定項目は `.env.example` にあります。

## 運用

```bash
docker compose ps                                        # healthy なら OK
docker compose logs --tail 20
curl -s http://127.0.0.1:8000/api/health; echo           # 稼働確認
git pull && docker compose up -d --build                 # 更新 (ソースだけの再ビルドは約1分)
sudo sqlite3 data/anime.db ".backup $HOME/backup-$(date +%F).db"   # バックアップ (要 sqlite3)
docker compose down                                      # 停止
sudo tailscale serve --https=443 off                     # serve の設定を外す
```

管理者のパスワードや認証アプリを失くして、ログインできなくなったときは、ホストで次を実行します。`-u app` は必須です。root では実行を断ります。

```bash
docker compose exec -u app app ani-cal user list                       # ユーザー一覧
docker compose exec -u app app ani-cal user reset-password <ユーザー名>  # 仮パスワードを1回だけ表示
docker compose exec -u app app ani-cal user reset-2fa <ユーザー名>       # 2段階認証を解除
```

`reset-password` と `reset-2fa` は、そのユーザーのログインをすべて解除します。データは `./data/anime.db` にあります。

Turnstile のキーを誤って、だれもログインできなくなったときは、次で無効にします (10秒ほどで反映)。

```bash
docker compose exec -u app app ani-cal turnstile off      # Botプロテクションを無効にする
docker compose exec -u app app ani-cal turnstile status   # 設定の確認
```

## 開発

```bash
cd app
DB_PATH=./dev.db BIND=127.0.0.1:8000 cargo run   # http://127.0.0.1:8000/
```

Rust 1.89 以上が必要です。画面 (`app/static/`) はビルド時にバイナリへ埋め込むので、変更したら再ビルドしてください。

## API (参考)

`admin` は管理者のみ使えます。

| メソッド | パス | 内容 |
|---|---|---|
| GET/POST | `/api/auth/setup` | 最初の管理者の登録待ちか／登録 (ユーザーがいない間だけ) |
| POST | `/api/auth/login` / `register` / `logout` / `logout_others` | ログイン (`otp` なしで2段階認証が必要なら `{totp_required:true}`)／招待コードでの登録／ログアウト／ほかの端末をログアウト |
| POST | `/api/auth/totp/setup` / `enable` / `disable` | 2段階認証の設定・有効化・無効化 |
| GET/POST | `/api/auth/me` / `password` | 自分の情報／パスワード変更 |
| GET/DELETE | `/api/auth/sessions` / `/api/auth/sessions/{id}` | ログイン中の端末の一覧／1つをログアウト |
| GET/POST/DELETE | `/api/invites` | 招待コードの一覧・発行・取り消し (admin) |
| GET/PATCH/DELETE | `/api/users` | ユーザー管理 (admin) |
| GET/POST | `/api/turnstile` / `/api/turnstile/disable` | Botプロテクションの状態／設定／無効化 (admin。設定・無効化はパスワードが必要) |
| GET | `/api/health` / `/api/status` | 稼働確認／取得状況 |
| POST | `/api/sync` / `/api/sync/cancel` | 取得の開始 (`{start, end}` で期間指定)／中断 (admin) |
| GET | `/api/logs` / `/api/coverage` | 取得履歴／取得済みの期間 (admin) |
| GET | `/api/catalog` / `/api/titles/{tid}/channels` | 作品一覧／作品の媒体別の放送 |
| GET/POST | `/api/tracks` | 登録作品の一覧 (`?archived=true` 視聴済み、`?dropped=true` 視聴中断)／登録 |
| PATCH/DELETE | `/api/tracks/{id}` | 作品の編集／解除 |
| POST | `/api/tracks/{id}/generate` / `watch_all` / `resync` | 予測話の作成／一括視聴／取得データの再反映 |
| POST | `/api/tracks/{id}/archive` / `drop` / `unarchive` | 視聴済みへ／視聴中断へ／登録作品へ戻す |
| GET/POST | `/api/tracks/{id}/episodes` | 話の一覧／追加 |
| PATCH/DELETE | `/api/episodes/{id}` | 話の編集／削除 |
| POST | `/api/episodes/{id}/revert` | 取得値に戻す |
| GET/POST | `/api/push/{key,settings,subscribe,unsubscribe,test}` | 通知の購読と設定 |
| GET | `/api/calendar?start=&end=` / `/api/backlog` | 期間内の話／配信済みで未視聴の話 |
